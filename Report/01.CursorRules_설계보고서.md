# Gilded Rose Cursor Rules Report

## 1. Purpose

This report summarizes the project-level Cursor AI rules added for the Gilded Rose C++17 legacy codebase.

The rule file was created to ensure that future AI-assisted QA, testing, and refactoring work follows the project's technical stack, legacy constraints, and behavior-preserving workflow.

## 2. Created Rule File

- File: `.cursorrules`
- Location: project root
- Target project: Gilded Rose C++17
- Main purpose: guide Cursor AI during legacy QA and refactoring tasks

## 3. Technology Stack Covered

The rule file explicitly defines the expected project stack:

- C++17
- CMake
- Google Test
- gcov/lcov for coverage checks

These rules help keep future implementation, build, and test work aligned with the existing C++ project structure.

## 4. Absolute Domain Rules

The `.cursorrules` file records the following non-negotiable constraints:

- The `Item` struct must not be modified.
- Existing public behavior must be preserved unless a change is explicitly requested.
- `quality` must remain between `0` and `50`.
- `Sulfuras` is the only exception to the normal quality range rule.
- `sellIn` may become negative.
- No implementation should block or normalize negative `sellIn` values.

These constraints reflect the Gilded Rose requirements and protect the legacy public interface.

## 5. Testing Rules

The rule file requires future behavior changes to be supported by Google Test tests using:

- `TEST_F` fixtures for behavior tests
- Given-When-Then test structure
- Boundary values for `quality = 0`, `quality = 50`, `sellIn = 0`, and `sellIn = -1`

The rules also require tests to focus on externally observable item behavior: item name, `sellIn`, and `quality`.

## 6. Refactoring Rules

The refactoring guidance is intentionally conservative:

- Refactor only while the test suite is Green.
- Do not change behavior during refactoring.
- Make small, incremental changes.
- Prefer named constants over magic numbers.
- Prefer simple and explicit C++ code.
- Run the full Google Test suite after refactoring.

This keeps legacy refactoring safe and reviewable.

## 7. Result

The project now has a root-level `.cursorrules` file that Cursor AI can use as persistent guidance for future Gilded Rose work.

The rules are suitable for QA, characterization testing, boundary testing, and behavior-preserving refactoring in this C++17 codebase.
