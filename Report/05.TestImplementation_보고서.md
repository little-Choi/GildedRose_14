# Gilded Rose Test Implementation Report

## 1. Purpose

본 보고서는 Gilded Rose C++17 프로젝트에 Google Test 기반 `TEST_F` 테스트 코드를 구현한 결과를 정리한다.

이번 테스트 구현의 목표는 Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 아이템별 핵심 동작과 경계값을 검증하고, 신규 Conjured 요구사항까지 포함해 `cmake --build build` 및 `ctest` 기준으로 Green 상태를 확보하는 것이다.

## 2. Modified Files

| File | Change Summary |
| --- | --- |
| `cpp/test/GildedRoseTest.cpp` | `TEST_F` 기반 테스트 픽스처 도입 및 아이템 타입별 테스트 케이스 작성 |
| `cpp/src/GildedRose.cpp` | Conjured 규칙 지원 및 품질 경계값 보정 로직 정리 |

`cpp/include/GildedRose.h`와 `cpp/include/Item.h`는 변경하지 않았다.

## 3. Test Fixture Design

테스트 파일은 Google Test의 `TEST_F` 구조로 재작성되었다.

공통 픽스처 `GildedRoseTest`는 단일 아이템을 준비하고 `GildedRose::updateQuality()`를 한 번 실행한 뒤 업데이트된 `Item`을 반환하는 `UpdateItem()` 헬퍼를 제공한다.

이를 통해 각 테스트는 다음 Given-When-Then 구조에 집중하도록 구성되었다.

- Given: 아이템 이름, 초기 `sellIn`, 초기 `quality` 정의
- When: `updateQuality()` 1회 실행
- Then: 변경 후 `sellIn`, `quality`를 `EXPECT_EQ`로 검증

## 4. Implemented Test Summary

총 26개의 `TEST_F` 테스트가 작성되었다.

| Item Type | Test Count | Main Coverage |
| --- | ---: | --- |
| Normal | 5 | 일반 품질 감소, `quality == 0`, `sellIn == 0`, `sellIn == -1`, 하한 보정 |
| Aged Brie | 5 | 품질 증가, 만료 당일/이후 2 증가, `quality == 49/50` 상한 보정 |
| Backstage Pass | 6 | 11일/10일/5일 임계값, 상한 50, 판매 당일 및 이후 0 처리 |
| Sulfuras | 5 | `sellIn` 불변, `quality` 80 불변, `sellIn == 0/-1` 예외 검증 |
| Conjured | 5 | 일반 아이템 대비 2배 감소, 만료 당일/이후 4 감소, 하한 0, 접두사 판별 |

요구 조건인 아이템 타입별 최소 5개 테스트를 모두 충족한다.

## 5. Boundary Value Coverage

이번 테스트는 다음 고위험 경계값을 포함한다.

| Boundary | Covered By |
| --- | --- |
| `quality == 0` | Normal 품질 하한 테스트 |
| `quality == 50` | Aged Brie 상한 유지 테스트, Conjured 상한 시작값 감소 테스트 |
| `quality == 49` | Aged Brie 및 Backstage Pass 상한 보정 테스트 |
| `sellIn == 0` | Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 판매 당일 테스트 |
| `sellIn == -1` | Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 만료 후 테스트 |
| `quality == 80` | Sulfuras 전설 아이템 예외 테스트 |

특히 `sellIn == 0`은 업데이트 후 `sellIn == -1`이 되면서 만료 규칙이 적용되는 고위험 조건이므로 각 아이템 타입에서 명시적으로 검증했다.

## 6. Conjured Implementation Result

기존 구현에는 Conjured 전용 분기가 없어 Conjured 테스트를 추가하면 실패하는 상태였다.

Green 상태 확보를 위해 `cpp/src/GildedRose.cpp`에 다음 구현을 반영했다.

- `"Conjured"`로 시작하는 아이템을 Conjured로 판별
- 판매 기한 전에는 `quality`를 2 감소
- 판매 기한 당일 또는 이후에는 `quality`를 4 감소
- `quality`가 0 미만으로 내려가지 않도록 보정
- Sulfuras는 가장 먼저 예외 처리하여 `sellIn`, `quality`를 변경하지 않음

품질 보정은 `IncreaseQuality()`와 `DecreaseQuality()` 헬퍼로 분리하여 `0 <= quality <= 50` 규칙을 한 곳에서 관리하도록 했다. Sulfuras의 `quality == 80`은 기존 요구사항대로 예외로 유지된다.

## 7. Verification Result

최근 편집 파일 기준 linter 진단 결과는 이상 없음이다.

빌드 및 테스트 검증 결과:

```bash
cmd /c "cmake --build build && ctest --test-dir build --output-on-failure"
```

결과:

- Build: Success
- Test total: 26
- Passed: 26
- Failed: 0
- Result: 100% tests passed

주의 사항:

- 현재 PowerShell 환경에서는 `cmake --build build && ctest`의 `&&` 구문이 파서 오류를 발생시켰다.
- 저장소 루트에서 `ctest`만 실행하면 테스트 설정 파일을 찾지 못한다.
- 실제 등록된 Google Test 실행은 `ctest --test-dir build --output-on-failure` 기준으로 정상 Green이다.

## 8. Conclusion

`cpp/test/GildedRoseTest.cpp`는 요구된 C++17, Google Test, `TEST_F`, Given-When-Then 주석 구조를 충족하도록 완성되었다.

Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 전 아이템 타입에 대해 최소 5개 이상의 테스트가 작성되었고, `EXPECT_EQ` 기반으로 `sellIn`과 `quality`의 외부 관찰 가능한 동작을 검증한다.

Conjured 신규 요구사항까지 구현에 반영되어 현재 빌드 및 테스트 결과는 Green 상태다.
