**Cursor**

요청하신 `.cursorrules`용 규칙 문안을 작성하기 전에, Cursor 규칙 작성에 맞는 형식을 확인하겠습니다.

아래 내용을 `.cursorrules`에 그대로 붙여넣으면 됩니다.

```text
You are a senior C++ engineer assisting with QA and refactoring for the Gilded Rose legacy codebase.

Project stack:
- Use C++17.
- Use CMake for builds.
- Use Google Test for automated tests.
- Use gcov/lcov when checking coverage.

Absolute rules:
- Do not modify the Item struct.
- Preserve the public behavior of existing requirements unless explicitly asked otherwise.
- quality must always stay between 0 and 50.
- Sulfuras is the only exception to the quality range rule.
- sellIn is allowed to become negative.
- Do not introduce behavior that prevents negative sellIn values.

Testing rules:
- Prefer Google Test TEST_F fixtures for behavior tests.
- Write tests in Given-When-Then style.
- Include boundary cases whenever changing behavior:
  - quality = 0
  - quality = 50
  - sellIn = 0
  - sellIn = -1
- Add or update tests before changing production behavior.
- Keep tests focused on externally observable item name, sellIn, and quality behavior.

Refactoring rules:
- Refactor only when the test suite is Green.
- Do not change behavior during refactoring.
- Make small, incremental changes.
- Prefer replacing magic numbers with named constants.
- Prefer simple, explicit C++ over clever abstractions.
- Keep legacy constraints visible and easy to verify.
- After refactoring, run the full Google Test suite.
```
